# پنجره روشنایی | Panjereh Roshanayi

پروژه دانشگاهی طراحی و پیاده‌سازی وب‌سایت معرفی خدمات کلینیک پنجره روشنایی.

## اجرای نسخه نمایشی

فایل `index.html` را در مرورگر باز کنید یا با افزونه Live Server در VS Code اجرا کنید. طراحی صفحات، تصاویر و تعاملات سمت کاربر قابل نمایش‌اند.

## ساختار پروژه

- `index.html` — صفحه اصلی
- `css/style.css` — استایل‌ها
- `js/script.js` — تعاملات صفحه و اعتبارسنجی فرم
- `images/` — تصاویر و آیکون‌های سایت
- `_worker.js` — بک‌اند Cloudflare Pages برای نوبت‌دهی، حساب کاربری، پیگیری، پنل مدیریت و فرم تماس

## اجرای بک‌اند و فرم تماس

فرم تماس در اجرای محلی ایمیل واقعی ارسال نمی‌کند. ارسال ایمیل به پیکربندی امن متغیرهای محیطی در Cloudflare و سرویس Resend وابسته است. هیچ کلید API یا اطلاعات محرمانه‌ای در این مخزن قرار ندهید.

این بسته نسخه Cloudflare است؛ پیکربندی PHP هاست cPanel در آن قرار ندارد. تصاویر فضای کلینیک نمایشی‌اند و عکس واقعی محل نیستند.

## پنل مدیریت نوبت‌ها (Cloudflare Pages)

- مسیر پنل: `/admin.html`
- رابط مدیریت: ورود، مشاهده فهرست (تا ۱۰۰ مورد)، فیلتر تاریخ/وضعیت، تأیید و لغو نوبت، خروج.
- مسیرهای API: `/api/admin/login`، `/api/admin/session`، `/api/admin/logout`، `/api/admin/appointments` و `PATCH /api/admin/appointments/:id`.
- در **Cloudflare Pages → Settings → Variables and Secrets** برای محیط **Production** یک **Secret** با نام دقیق `ADMIN_PASSWORD` و یک رمز تصادفی قوی با **حداقل ۱۶ نویسه** تعریف کنید. رمز را در GitHub، README یا چت قرار ندهید.
- اتصال D1 به نام `DB` لازم است. جداول `admin_sessions` و `admin_login_attempts` هنگام اولین تلاش ورود ساخته می‌شوند؛ نسخه SQL آن‌ها در `schema.sql` هم آمده است.
- پس از تنظیم Secret و آپلود مجدد **تمام فایل‌های نسخه جدید پروژه** (از جمله `_worker.js` و `admin.html`) به Cloudflare Pages، پنل در `https://panjere-roshanayi.pages.dev/admin.html` در دسترس خواهد بود.
- این مخزن به Cloudflare Pages به‌صورت خودکار متصل نیست؛ هر تغییر GitHub باید جداگانه در Cloudflare منتشر شود.
- امنیت: نشست‌های ۸ ساعته با کوکی HttpOnly/Secure/SameSite=Strict، نگهداری هش توکن در D1، محدودسازی تلاش ناموفق ورود، بررسی Origin برای تغییرات و درخواست‌های بدون کش. تغییر رمز، نشست‌های موجود را خودکار باطل نمی‌کند؛ برای ابطال همه نشست‌ها، جدول `admin_sessions` را خالی کنید.
- پنل برای **پروژه آموزشی و داده‌های آزمایشی** است؛ پیش از استفاده واقعی با اطلاعات بیماران، بازبینی امنیت و حریم خصوصی، کنترل دسترسی دقیق‌تر و سیاست نگهداری داده ضروری است.

## پیگیری وضعیت نوبت

- صفحه عمومی: `/tracking.html`؛ از صفحه اصلی و صفحه رزرو هم قابل دسترسی است.
- API: `POST /api/appointments/track` با `{ "reference": "A1B2C3D4", "phone": "09123456789" }`.
- برای جلوگیری از افشای وضعیت نوبت صرفاً با کد ۸ کاراکتری، **کد پیگیری و همان شماره موبایل ثبت‌شده** هر دو الزامی‌اند.
- پاسخ فقط تاریخ، ساعت و وضعیت (`pending`، `confirmed`، `cancelled`) را برمی‌گرداند؛ نام، شماره موبایل و سایر اطلاعات شخصی بازگردانده نمی‌شوند.
- محدودسازی ۱۰ درخواست در هر پنجره ۱۵ دقیقه‌ای برای هر IP با هش IP در جدول `tracking_attempts` دیتابیس D1. این جدول خودکار ایجاد می‌شود.
- تغییرات GitHub تا زمان آپلود مجدد پوشه کامل پروژه در **Cloudflare Pages → Deployments → Create deployment → Production** روی سایت زنده ظاهر نمی‌شوند.
- این پیاده‌سازی برای **نمایش دانشگاهی با داده‌های آزمایشی** است و پیش از کاربرد واقعی پزشکی به بررسی مستقل امنیت و حریم خصوصی نیاز دارد.

## حساب کاربری مراجعه‌کنندگان (نسخه آزمایشی)

- صفحه: `/account.html` با تب‌های ثبت‌نام و ورود، و بخش خصوصی «نوبت‌های من».
- API: `POST /api/account/register`، `POST /api/account/login`، `GET /api/account/session`، `POST /api/account/logout` و `GET /api/account/appointments`.
- شماره موبایل (شناسه ورود)، نام کامل و رمز حداقل ۵ کاراکتری. رمز خام ذخیره نمی‌شود؛ PBKDF2-SHA256 با ۲۱۰هزار تکرار و salt تصادفی استفاده می‌شود.
- نشست‌ها با کوکی HttpOnly/Secure/SameSite=Strict و انقضای ۲۴ ساعته؛ توکن نشست به‌صورت هش در D1 ذخیره می‌شود. برای ثبت‌نام/ورود محدودیت درخواست مبتنی بر IP وجود دارد.
- نوبت‌هایی که **هنگام ورود کاربر** ثبت شوند، با `appointments.user_id` به حساب متصل می‌شوند؛ API خصوصی فقط نوبت‌های همان `user_id` را بازمی‌گرداند.
- **نوبت‌های مهمان قبلی عمداً خودکار به حساب جدید وصل نمی‌شوند**؛ شماره موبایل بدون OTP قابل راستی‌آزمایی نیست. پیگیری مهمان با کد پیگیری و شماره موبایل در `tracking.html` باقی می‌ماند.
- جداول `users`، `user_sessions` و `user_auth_attempts` و ستون `appointments.user_id` در اولین استفاده از API حساب کاربری به‌صورت خودکار ساخته/اضافه می‌شوند. `schema.sql` مستندات این ساختار را دارد.
- **هشدار:** این پروژه صرفاً برای تست دانشگاهی با داده ساختگی است. تأیید مالکیت شماره با OTP، بازیابی رمز، مقررات حفاظت داده‌های سلامت، بازبینی امنیت مستقل و زیرساخت مناسب استفاده بالینی هنوز فراهم نشده‌اند. با اطلاعات واقعی بیماران آزمایش نکنید.
- انتشار تغییرات به Cloudflare Pages **دستی** است: آخرین ZIP مخزن را استخراج و تمام فایل‌ها را به Production آپلود کنید.

### لغو نوبت توسط مراجعه‌کننده

- کاربر واردشده می‌تواند نوبت‌های **آینده** خودش را از بخش «نوبت‌های من» لغو کند.
- مسیر `POST /api/account/appointments/cancel` فقط با نشست معتبر، بررسی مالکیت نوبت و زمان محلی تهران کار می‌کند.
- وضعیت به `cancelled` تغییر می‌کند و رکورد برای سابقه باقی می‌ماند؛ زمان لغوشده با ایندکس نوبت‌های فعال مجدداً آزاد می‌شود.
- تغییر تاریخ نوبت برای کاربر در این نسخه ارائه نشده است.

## چک‌لیست بررسی نهایی نسخه دانشگاهی

پس از انتشار **یک‌باره** نسخه نهایی در Cloudflare Pages، با اطلاعات کاملاً ساختگی این مسیرها را آزمایش کنید:

1. صفحه اصلی: نمایش منظم هدر در موبایل و دسکتاپ، باز و بسته شدن منو، کارکرد لینک‌ها.
2. حساب مراجعه‌کننده: ثبت‌نام با رمز حداقل ۵ کاراکتری، ورود، خروج و ورود مجدد.
3. رزرو: در حالت ورود به حساب، انتخاب روز غیرجمعه و ساعت آزاد، ثبت درخواست و دریافت کد پیگیری.
4. «نوبت‌های من»: نمایش نوبت ثبت‌شده فقط برای صاحب حساب.
5. لغو نوبت آینده: تغییر وضعیت به «لغوشده» و آزاد شدن ساعت برای رزرو مجدد.
6. پیگیری: نمایش وضعیت با کد پیگیری و موبایل درست، و عدم نمایش با شماره اشتباه.
7. پنل مدیریت: ورود مدیر، مشاهده نوبت آزمایشی، تأیید یا لغو آن.
8. بررسی خطاها: رزرو دوباره همان ساعت فعال، ورود اشتباه و نوبت گذشته.

**نکته:** GitHub به Cloudflare Pages متصل نیست. ذخیره تغییرات در GitHub به معنی انتشار در سایت زنده نیست. قبل از تست عملی روی نسخه جدید، باید فایل‌های کامل مخزن را در Production منتشر کنید. این پروژه برای اطلاعات واقعی درمان‌جویان آماده نیست.
